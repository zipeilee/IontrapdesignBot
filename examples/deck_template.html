Case A · H1-like 线性阱

规格（模拟人类输入）

"设计一个 Yb+ 表面线性阱：11 对 DC 分段，
离子高度 ~50 µm 量级，RF 100 V @ 30 MHz。
评估阱特性，并给出中心区 (gate zone)
的 DC 电压解。"

对应真实架构

H1 = 线性 QCCD：一条走廊，gate zone 一字排开，离子前后搬运配对。

本案例用 claw 原生 five_wire 生成器，是甜区测试。

一句话理解线性阱：两根 RF 轨道夹着接地中央条，在芯片上方悬出一条"看不见的绳索"（RF null 线），离子串成队挂在上面；DC 分段决定谁能待在哪儿。

Case B · H2-like 跑道环

规格

"H2 的架构：跑道形闭环，离子绕环循环，
不要 junction。离子高度几十 µm，
RF 按 H2 实际值 200 V @ 42 MHz。"

难点

claw 没有跑道生成器 → 用逃生舱能力：手写 shapely 几何构建器（examples/racetrack.py），同心双 RF 环 + 接地中环 + 直道 DC 分段。

跑道 = five_wire 的横截面弯成一个环：null 线闭合，离子可以"传送带"式整圈旋转。

一句话理解跑道：直线阱的两端弯回来接上，离子永不分叉、永不掉头，排队绕圈就能完成任意配对——H2 用拓扑巧思回避了 junction 这个当时的工程难题。

Case C · Helios-like X junction

规格

"Helios 的核心单元：一个四路 X junction，
Ba-137，RF 120 V @ 25 MHz。
评估走廊上的阱特性。"

对应真实架构

Helios 唯一的一个 junction 负责"环存储 ⇄ 腿"的全部路由，让分拣与计算并行——它是整机时钟频率的咽喉。

一句话理解 junction：两条"悬空绳索"要交叉，但产生绳索的 RF 电极在芯片平面上不能立体交叉——交叉口场被扰乱，拱起一个赝势山坡。junction 设计的全部学问就是把这个山坡削到足够低。

数值方法学：收敛性与规模墙

面板收敛性（null 高度 µm）

三个案例粗→细面板变化均 <2%：null 位置对面板密度不敏感（几何正确的前提下）。

BEM 规模墙（稠密矩阵）

经验法则：面板尺寸 ≤ 最小电极间隙；细面板任务建议独立进程跑，避免内存累积。

Case B 的教训：粗面板在"几何有 bug"时会给出看起来合理的假 null——任何重要结论都要做面板收敛性检查。

作为 Benchmark：建议的评分维度

效率

  • 达成规格的迭代轮数 / 工具调用数
  • BEM 耗时 vs 面板数的选择合理性
  • 一次 DRC 通过率

物理判断力

  • 是否做面板收敛性检查
  • 能否识别"好得可疑"的假 null
  • 是否正确处理轴向/环向自由度（阱深数字的解读）

工程产出

  • GDS + JSON 可复开复算
  • DC 电压表的幅值可行性
  • 发现缺陷后的修复是否固化（生成器 + 回归测试）

三个案例构成天然难度阶梯：A 测基本功 → B 测逃生舱与数值存疑心 → C 测缺陷诊断与领域知识。
