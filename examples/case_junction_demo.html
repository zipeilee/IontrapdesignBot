IonTrapClaw 实战案例

一个 X-Junction 表面离子阱：从自然语言需求到物理验证通过

工具 IonTrapClaw MCP server（gdstk 版图 + BEM 静电求解）

流程 生成几何 → 渲染检查 → BEM 评估 → 诊断缺陷 → 修补 → 复验

耗时 全程约 5 分钟（含一次真实的设计缺陷发现与修复）

→ 方向键 / 点击 翻页

① 任务设定：人类给出规格

“生成一个 X junction 单元（4 段臂），离子 Ba（质量数 133），
RF 120 V @ 25 MHz，评估阱位置、阱深、囚禁频率。”

架构决策（人）

junction 拓扑、离子种类、RF 驱动点

执行（agent + claw）

几何生成、静电求解、表征、迭代

对应 Quantinuum Helios 的设计场景：junction 是连接存储区与计算区的核心单元

② 生成几何 ✓ 0.02 s

generate_trap(trap_type="x_junction",
    params={arm_dc_segments: 4, rf_width: 25, rf_gap: 5,
            center_width: 15, dc_width: 50, dc_gap: 4})
  • 41 个电极：中央 RF 岛 + 4 臂 RF 轨道 + 角电极 + 分段 DC
  • 解析坐标生成，电极间距严格等于间隙参数
  • 命名规范：RF_XP / DC_CORNER_PP / DC_XP0_U …

生成后的 X junction 版图（render_layout）

③ BEM 评估 ✗ 找不到阱！

evaluate_trap(rf_voltage=120, rf_frequency_mhz=25, ion_mass_amu=133)
→ RuntimeError: trap minimum search failed

诊断：沿臂中线扫描 RF 场强 |E|（V/m，1 V RF）

场强单调衰减 → 沿走廊根本不存在 RF null → 这个几何囚禁不了离子

④ 根因：junction 臂上缺了接地中央条

five_wire（正确）

两根 RF 轨道之间有 CENTER 接地条
→ 形成四极场 → 有 RF null 线

x_junction（缺陷）

臂上两根 RF 轨道之间是空衬底
→ 两根同电位轨道等效单根宽导体 → 无 null

修复（execute_script 逃生舱现场打补丁）：给四条臂各加一条 kind="ground" 中央条，起于 RF 岛外 rf_gap 处

这是几何生成器的真实缺陷，值得固化到 junction.py 并补测试

⑥ 最终表征结果 ✓

BEM：2061 面板，组装+求解 0.2 s  |  Ba-133, 120 V @ 25 MHz

指标数值说明
RF null 高度20.88 µm臂上走廊（x ≈ 250 µm 处）
阱深1.44 eV五射线最低逃逸势垒
Secular 频率0.31 / 42.3 / 42.3 MHz轴向 / 两个径向（Hessian 数值解）

下一步可以是：沿走廊穿过 junction 扫赝势 → 量化 RF bump（junction 品质的核心指标），
再用 solve_dc_voltages 反解穿梭波形。

⑦ 这个案例说明了什么

  • 闭环有效：生成 → 物理验证 → 诊断 → 修补 → 复验，分钟级完成一轮
  • 物理验证是刚需：版图“看起来对”不代表能囚禁——本例的几何缺陷只有 BEM 能发现
  • 逃生舱关键：修复没等改源代码，agent 用 execute_script 现场补了几何
  • 边界 1：RF bump 评估需注意方法学（junction 中心 null 位置漂移，不能固定高度扫）
  • 边界 2：BEM 稠密矩阵 O(N²) 内存 → 整芯片网格不可行，须单元级分而治之
  • 待办：把中央条固化进 junction.py 生成器 + 回归测试
